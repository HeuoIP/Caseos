# Sprint 09 -- Decision Intelligence V1

## Goal

Upgrade CaseOS from a rule-based recommendation engine into a hybrid
AI decision system. This sprint does NOT add new AI features; it
integrates the existing Vision Engine, Knowledge Library, Decision
Rules, and Object Library into one end-to-end pipeline that can be
explained, extended, and replayed.

- Decision Engine: backend/app/core/decision/engine.py

## Decision Pipeline Upgrade

New default pipeline:

    space -> decision_maker -> knowledge_retriever -> strategy -> object_selector -> explain

The Knowledge Retriever is placed between the Decision Maker and
the Strategy Agent so that every downstream agent has the relevant
knowledge slices already loaded into the shared DecisionContext.

## Knowledge Retriever (V1)

Pure local, deterministic, no vector database, no LLM. The
retriever takes a Vision JSON plus an optional decision context
dict and returns a RelevantKnowledgeContext with six ranked slices:

- related_cases      -- similar cases from data/analysis/cases/
- related_themes     -- themes from knowledge/taxonomy/theme/*.md
- related_objects    -- objects from knowledge/objects/*.md
- related_rules      -- rules from knowledge/decision_rules/*.md
- related_handbook   -- expert handbook from knowledge/expert_handbook/*.md
- related_reasoning  -- reasoning patterns from knowledge/reasoning/*.yaml

Per-slice caps are conservative and tunable: TOP_THEMES=5,
TOP_OBJECTS=8, TOP_RULES=3, TOP_HANDBOOK=4, TOP_REASONING=5.

Ranking is keyword-overlap (Jaccard) plus theme alignment boost
and theme exclusion penalty. The retriever never invents IDs and
only references files on disk.

## Strategy Agent Upgrade (LLM-style reasoning)

The agent still uses a deterministic rule-based strategy selector
(Goal x Strategy x Conflict resolution, ADR-005). The Sprint 9
upgrade is that it now also emits a StrategyAnalysis dataclass
that mirrors the four prose fields an LLM would produce:

`python
StrategyAnalysis(
    space_positioning: str     # how the space is framed
    core_problem: str          # what the venue must solve
    design_direction: str      # the lead design move
    investment_logic: str      # where the budget concentrates
    confidence: float          # 0.0 - 1.0
    related_strategy_ids: list
    related_goal_ids: list
    knowledge_refs: list       # theme:* / handbook:*
)
`

The text is generated by deterministic template composition; an
LLM can replace the renderer later without changing the agent
interface or the context schema.

## Explain Agent Upgrade (customer-facing)

The new template is one sentence per recommendation, customer-
facing, and avoids marketing words. Concretely it never uses:

- striking, amazing, iconic, world-class

and it never uses AI-jargon (embedding, neural, model, etc.).
It uses physical features, the chosen theme, the user goal, and
the strategy direction.

The default template is:

    "{object} brings {benefit}. It fits {theme_benefit} and serves {goal}, while {strategy_direction}."

strategy_direction is StrategyAnalysis.design_direction if
present, so the explanation is consistent with the strategic frame.

## Markdown Report Additions

The renderer now emits two extra sections, in the right order:

- ## Retrieved Knowledge     -- themes, objects, rules, handbook,
                                   reasoning patterns, similar cases
- ## Strategy Analysis        -- positioning / core problem /
                                   direction / investment logic

Existing sections (Space, Decision Maker, Strategies,
Top Recommendations, Explanations) are unchanged.

- [x] Retrieved Knowledge
- [x] Strategy Analysis
- [x] Strategies (with the kept strategy list)
- [x] Top Recommendations
- [x] Explanations (customer-facing, no marketing words)

## Out of Scope (deferred)

- No vector database (pure local retriever, Jaccard ranking).
- No real LLM call inside the pipeline (templates are deterministic).
- No image generation.
- No PDF.
- No UI.
- No new agent beyond knowledge_retriever.
