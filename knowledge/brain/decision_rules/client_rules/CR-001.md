# CR-001 -- Do not design before project definition

## 1. Rule ID

CR-001

## 2. Rule Name

Do not design before project definition

## 3. Applicable Scenario

Client requirement is unclear at intake.

## 4. Observation Conditions

The intake transcript shows the client cannot clearly
explain at least one of:

- Why they want the project.
- Target users.
- Expected outcome.
- Project goal.

## 5. Judgment

Project definition is incomplete.

## 6. Reasoning

Design solves problems.

Undefined problems cannot produce correct solutions.

This is a direct binding of Constitution V1 Principle
003 (Understand before recommending).

## 7. Recommended Action

Start the **client discovery process** before any
design work.

Issue the Client Understanding discovery questionnaire
(see `knowledge/brain/client_understanding/README.md`).
The product layer should surface a "Tell us more" step
in place of any design step until four signals are
captured.

## 8. Exceptions

The rule may not fire if the user has explicitly
chosen "Not sure" for any of the four signals AND has
provided a concrete project context (site photo,
project type). In that case, the rule downgrades to a
warning and the next-stage Project Fit Agent proceeds
with `confidence = inferred`.

## 9. Example Cases

- A kindergarten director uploads a courtyard photo
  with no other context; the agent must ask who, what,
  and why before recommending anything.
- A commercial plaza owner asks for "a beautiful
  playground"; the rule fires -- "beautiful" is not a
  project definition.
