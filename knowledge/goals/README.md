# Goal Library

The Goal Library is the most important knowledge table in CaseOS.

It defines **WHY a space should be designed the way it is**.
Every Space Decision in CaseOS begins by matching one or more Goals.

## Why Goals First

- Decisions driven by Goals are explainable to clients.
- Goals connect business value with design choices.
- Goals make trade-offs visible.
- Goals enable cross-domain reasoning (playground <-> commercial <-> education).

## Cross-Links

- Goal <-> Object Category: via Suitable_Objects / Unsuitable_Objects.
- Goal <-> Theme: via Domain_Affinity and shared Suitable_Objects with knowledge/taxonomy/theme/.
- Goal <-> Decision Rule: via knowledge/decision_rules/Space_Decision_Principles.md.
- Goal <-> Expert Handbook: via knowledge/expert_handbook/ (especially 02_Expert_Rules.md, 05_Negative_Rules.md).

## Decision Pipeline

    Client brief
      |
      v
    1. Identify Goals (this library)
      |
      v
    2. Resolve Goal conflicts (Conflicts_With)
      |
      v
    3. Map Goals -> Suitable Object categories
      |
      v
    4. Map categories -> concrete objects (knowledge/objects/)
      |
      v
    5. Select Themes consistent with Goals (knowledge/taxonomy/theme/)
      |
      v
    6. Apply Decision Principles (knowledge/decision_rules/)
      |
      v
    7. Generate proposal

## Maintenance Rules

1. Goal_ID is **stable**. Never rename an existing ID; add a new one if needed.
2. The 5-level priority (star count) is the only allowed priority scale.
3. Object category names must stay in sync with knowledge/objects/ and knowledge/taxonomy/theme/.
4. New Goals should reference existing Goals via Related_Goals or Conflicts_With.
5. Every change updates _index.yaml (regenerated by this renderer).
